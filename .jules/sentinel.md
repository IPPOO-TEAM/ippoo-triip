## 2025-06-27 - Centralized CSS Sanitization for Dynamic Chart Styles
**Vulnerability:** Dynamic custom properties (CSS variables) were injected into a `<style>` tag using `dangerouslySetInnerHTML` in the `ChartStyle` component (`chart.tsx`). Because `id`, `key`, and `color` properties were raw string values, malicious inputs could break out of the style rules (using characters like `}`, `;`, etc.) to perform CSS injection or exploit browser vulnerabilities (e.g., using `url()`, `expression()`, or script injection).
**Learning:** Recharts wrapper components styled with dynamic CSS variables can be an entry point for XSS or CSS injection when parameters are controlled or influenced by external data sources (like user names, dynamic theme colors). Even when used inside chart helper components, any dynamic raw string injection into CSS selectors/rules must be strictly sanitized.
**Prevention:** Strictly sanitize identifiers used in style attributes or `<style>` blocks (only allow safe characters: `/[^a-zA-Z0-9-_]/g`). Sanitize values by stripping rule-breaking characters like `;`, `}`, `\` and blocking unsafe prefixes or tags like `url(`, `expression(`, `javascript:`, or `</style>`.
